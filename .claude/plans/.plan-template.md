# Plan file schema

Shared structure used by `/ai:task` and `/ai:feature`. The plan file is the
single source of truth for an active piece of work — `/ai:handoff`,
`/ai:resume`, `/ai:status`, and `/ai:task-finish` all read from it.

Save plans at `.claude/plans/$SLUG.md` where `$SLUG` is the sanitized task
or feature name (lowercase, hyphenated, special chars stripped, max 50
chars).

## Base schema (used by Task and Feature)

```markdown
# {{Task|Feature}}: {{original-name}}

**Started:** YYYY-MM-DD
**Status:** {{planning | contract-design | in-progress | blocked | done}}
**Source spec:** {{.claude/plans/specs/<slug>.md if a spec exists, otherwise omit this line}}

## Goal
{{one clear sentence describing what this work achieves}}

## Plan
1. {{step}} — rationale
2. {{step}} — rationale

## Files affected
- `path/to/file` — reason for change

## Components involved
- {{component}} — role in this work

## Acceptance criteria
- [ ] criterion 1
- [ ] criterion 2

## Risks and edge cases
- {{risk}}

## Open questions
- {{question that must be answered before or during implementation}}

## Decision log
| Date | Decision | Rationale | Impact |
|------|----------|-----------|--------|
| YYYY-MM-DD | Initial plan approved | — | — |

---
*last-updated: YYYY-MM-DD HH:MM*
```

## Feature extension

For `/ai:feature` (cross-component work), insert a `## Contract` section
between `## Goal` and `## Plan`:

```markdown
## Contract

### Components involved
- {{component}} — role in this feature

### Interface definitions
{{API schema, event format, or shared type definitions}}

### Constraints
{{what must be true across all implementations}}

### Implementation order
{{sequential or parallel — be explicit about dependencies}}
```

The Feature variant uses `**Status:** contract-design` initially, then
transitions to `in-progress` once the contract is approved.

## Rules for the plan owner

- **Update on every scope-affecting decision** — append a row to the
  Decision log, bump `last-updated`.
- **Check off acceptance criteria** as they are met.
- **Update Status** as state changes (planning → in-progress → blocked → done).
- **Never delete the plan mid-work** — use `/ai:task-finish` to close,
  `/ai:task-delete` to discard.

The plan IS the source of truth. Handoff and resume depend on it being
current.
